# Genba Webサイト・リニューアル指示書

最終更新: 2026-08-11

関連資料: [09-pivot-business-plan.md](09-pivot-business-plan.md)

## 1. リニューアルの目的

既存サイトは、海外企業向けの英語中心アドバイザリーサイトとして設計されている。これを、日本の外資SaaS営業職向けの無料データメディアへ変更する。

リニューアル後の最重要行動は、問い合わせではなく以下とする。

1. 無料ニュースレターへの登録
2. 企業・求人ページの閲覧
3. 企業公式求人への遷移
4. 採用企業・スポンサーからの掲載問い合わせ

## 2. 実装方針

### 維持するもの

- Next.js 14 App Router
- TypeScript
- Tailwind CSS
- static export
- Cloudflare assets deployment
- Markdownベースの記事管理
- 日英対応可能な基盤

### 変更するもの

- 日本語を主言語にする
- トップページをメディア・データベース型へ全面変更
- Advisory、Services、既存Contact中心の導線を廃止・再配置
- 企業・求人・変更履歴を構造化データで管理
- ニュースレター登録を全ページの主要CTAにする
- 採用企業向けページを追加
- 既存の英語記事はアーカイブとして保持するが、トップ導線から外す

## 3. URL設計

推奨URLは以下。

| URL | 役割 |
|---|---|
| `/` | 日本語トップ |
| `/companies` | 外資SaaS企業一覧 |
| `/companies/[slug]` | 企業詳細・採用タイムライン |
| `/jobs` | 外資SaaS営業求人一覧 |
| `/jobs/[id]` | 求人詳細・公式応募リンク |
| `/signals` | 新規求人・終了・日本参入シグナル |
| `/insights` | 編集記事一覧 |
| `/insights/[slug]` | 記事詳細 |
| `/newsletter` | 無料ニュースレター登録 |
| `/advertise` | 求人掲載・スポンサー案内 |
| `/methodology` | 情報源・判定・訂正方針 |
| `/about` | Genbaと編集方針 |
| `/contact` | 一般・訂正・掲載問い合わせ |
| `/en/...` | 既存英語記事のアーカイブ候補 |

既存の `/ja` を日本語ルートとして残すのではなく、日本語をルート直下に移す。既存URLから301リダイレクトできないstatic export構成では、旧URLの保持またはHTMLレベルの移行案を検討し、検索評価を失わないようにする。

## 7. 企業詳細仕様

企業詳細は単なる会社概要ではなく、読者が「今この会社を見る価値があるか」「どの求人が自分の経験に近いか」「どの会社と併願比較すべきか」を判断するための`応募判断OS`として設計する。

### 営業視点サマリー

- ファーストビューで、営業候補者が「誰のどんな課題を解決する会社か」「営業として何が面白いか」を把握できる短い説明を表示する
- 原則3文とし、対象顧客とソリューション、顧客が抱える具体的な課題3点、関与できる部門・経営課題と提案拡張の面白さを順に記載する
- `です・ます`調を使わず断定調に統一し、求人タイトルの列挙や汎用的なSaaS紹介文で代替しない
- 公開情報とGenba仮説を混同せず、各社の`solutions`、`customerProof`、`sellingPlaybook`、`salesAppeal`と整合させる

### 応募判断サマリー

- 最上部に`今、見る価値が高い`、`条件が合えば有力候補`、`今はウォッチ候補`のいずれかを表示する
- 上記は企業の優劣、応募推奨、合格確率ではなく、確認中の求人件数と採用状況に基づく閲覧優先度とする
- 判定理由、確認中の営業求人数、採用シグナル数、最終更新日を併記する
- 向いている経験は、確認済み求人のセグメントと企業タグから一般的な近さとして示す
- 応募・合否実績と公開済み算出方法がない状態で、合格確率を数値表示しない

### 応募判断材料の充足度

- 採用状況、営業求人、ソリューション領域、日本拠点、OTE・Pay Mix、日本組織規模、Quota達成率、在籍・昇進データを主要8項目とする
- 確認できた項目だけをカウントし、未確認項目は空欄ではなく`未確認`と表示する
- 充足度は会社の評価点ではないことを画面上で明記する
- 各数字に対象地域、対象職種、期間、出典、最終更新日、サンプル数を持たせる

### 公開情報インテリジェンスとGenba仮説

情報が未開示であることだけを並べず、読者が応募仮説を立てられるよう、公開情報を次の2層で表示する。

1. `公開事実`: 企業公式、法定開示、公式求人、公式導入事例などから直接確認できる内容
2. `Genba仮説`: 複数の公開事実と外部集計を横断して導く、検証可能な編集上の読み解き

各Genba仮説には必ず以下を持たせる。

- 仮説の結論と確度（高・中・探索中）
- 仮説を支持する材料
- 仮説が外れる可能性を示す反証・留保
- 面接で検証できる具体的な質問
- 根拠URL、情報種別、対象地域・職種、最終確認日

企業公式、法定開示、外部集計、コミュニティ情報はラベルで分ける。グローバルの自己申告データを日本法人の事実として扱わず、コミュニティ情報だけを根拠に断定しない。OTE、Pay Mix、Quota達成率など非公開の数値は作らず、方向性の仮説と確認方法を示す。

スポンサー企業から提供された一次情報は`企業提供事実`として表示し、Genba仮説と分離する。対価により仮説の結論や併願順位を変更せず、提供事実によって仮説が変わる場合は更新理由と更新日を残す。

### ソリューション・ポジション・組織

- ソリューション領域、主なBuyer、解決課題、営業として得られる経験、面接で確認すべき論点を表示する
- ソリューションの強さは、国内導入事例、競合差別化、顧客継続・拡張などの証拠単位で示し、総合点だけで断定しない
- 求人ごとに勤務地、言語、セグメント、初回確認日、最終更新日を表示する
- OTE、Pay Mix、新規／既存比率、Quotaは公式情報等で確認できた場合だけ掲載する
- 日本社員数、AE人数、平均在籍年数、入社元、転職先は集計値とし、個人名一覧や人物評を作らない
- 日本責任者・営業リーダーは公式プロフィール、就任リリース、公開インタビューのみを参照する

### 併願候補

- 同じソリューションクラスター、Buyer、求人セグメント、企業タグの近さから最大3社を表示する
- `Genba分析`と明記し、競合関係や個人の合格可能性を断定しない
- スポンサー契約によって候補順位や分析理由を変更しない

### 出典台帳

- 企業公式Career、各求人、採用シグナル、法定開示、導入事例、外部集計、コミュニティ情報の根拠URLを重複排除して一覧化する
- 企業公式、法定開示、外部集計、コミュニティ情報をラベルで区別する
- ページ上の最終更新日と、内部データの最終確認日を区別して保持する

### 上部サマリー

- 企業名・公式URL
- 事業カテゴリ・本社
- 日本法人・日本語サイト
- 日本市場フェーズ
- 採用トレンド
- 営業求人数
- 最終更新日（内部データは最終確認日を保持）

### 日本市場シグナル

- 日本責任者
- 日本語サイト
- 国内顧客事例
- 営業求人
- SE・CS求人

- 日本向けイベント・製品対応

### 現在の求人

## 9. データモデル

初期はGit管理のJSONまたはYAMLを推奨する。企業数・変更頻度が増えたらDBへ移行する。

### Company

```ts
interface Company {
  slug: string;
  name: string;
  legalName?: string;
  logoUrl?: string;
  website: string;
  careersUrl: string;
  newsroomUrl?: string;
  headquarters: string;
  category: string[];
  descriptionJa: string;
  japanEntity: "yes" | "no" | "unknown";
  japaneseSite: boolean;
  japanPhase: "watching" | "entry" | "building" | "scaling" | "established" | "contracting" | "unknown";
  hiringTrend: "up" | "flat" | "down" | "unknown";
  lastVerifiedAt: string;
  sources: Source[];
}
```

### Job

```ts
interface Job {
  id: string;
  companySlug: string;
  title: string;
  role: "sdr" | "bdr" | "ae" | "am" | "manager" | "partner" | "se" | "cs" | "other";
  segment?: "smb" | "commercial" | "mid-market" | "enterprise";
  location: string;
  workStyle?: "onsite" | "hybrid" | "remote" | "unknown";
  languages?: string[];
  salaryText?: string;
  sourceUrl: string;
  firstSeenAt: string;
  lastSeenAt: string;
  status: "open" | "closed" | "unknown";
  sponsored: boolean;
}
```

### Signal

```ts
interface Signal {
  id: string;

  type: "job_added" | "job_removed" | "job_changed" | "japan_entity" | "leader_hired" | "customer" | "partner" | "localization" | "event" | "other";

  interpretationJa?: string;

```

```ts
interface Source {
  url: string;

```

## 10. 収集・更新フロー

### 情報源の優先順位

1. 企業公式Career・ATS・ニュースルーム・日本サイト
2. 信頼できる求人・報道媒体
3. X・LinkedIn・読者提供情報

### 日次処理

1. 登録済み企業の公式URLを巡回
2. 公開中求人を抽出
3. 前回スナップショットと比較
4. 追加・削除・変更候補を生成
5. 関連ニュースを照合
6. AIが職種、セグメント、信頼度を分類
7. 出典・取得日・差分を保存
8. デイリーブリーフ、X原稿、ニュースレター候補を生成
9. ガードレールとリンク切れを検査
10. 承認後に公開・デプロイ

### 収集上の制約

- robots.txt、利用規約、アクセス頻度を尊重する
- ログインや回避技術が必要な取得は行わない
- 求人媒体を公式Careerの代替ソースとして無断複製しない
- 取得できない情報を推測で埋めない
- 自動収集が許されないサイトは手動確認または公式フィードを利用する

## 20. 受入条件

### 機能

- 20社以上の企業データが表示できる
- 企業・求人のフィルターとソートが機能する
- 求人追加・終了履歴が企業タイムラインに表示される
- 公式求人への遷移を計測できる
- ニュースレター登録ができる
- スポンサーと通常コンテンツが明確に区別される
- 出典と最終更新日が全データページに表示される

### 品質

- `npm run build`成功
- TypeScriptエラーなし
- モバイル・デスクトップで主要導線が崩れない
- 主要ページに固有title、description、canonicalがある
- 内部リンク切れなし
- 同一企業・求人の重複なし
- 求人終了後の表示方針が機能する
- WCAGを意識したコントラストとキーボード操作

### 運用

- 日次更新が自動下書きまで進む
- 公開前に変更件数・出典・リスクが一覧表示される
- 承認されない変更は公開されない
- 失敗時に既存公開データを壊さない
