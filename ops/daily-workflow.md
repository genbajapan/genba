# Genba日次運用・共有ワークフロー

このワークフローはCodexとClaude Codeで共用する。ツール固有のコマンドやスキルへ内容を複製しない。

## 0. 開始確認

1. `PROJECT_RULES.md`を読む
2. `ops/job-publication-and-sponsor-policy.md`と`ops/guardrails.md`を読む
3. `git status --short`で他の作業を確認する
4. `lib/market-data.ts`、直近の公開記事、X下書き、更新日を確認する
5. 他方のエージェントによる未完了変更と競合する場合は上書きせず停止する

## 1. 公式情報を調査する

登録企業の公式Career、公式ATS、公式ニュースルーム、日本公式サイトを確認する。

- 新規求人
- 募集終了
- 職種名、勤務地、担当領域、要件の変更
- 日本組織の採用拡大を示す公式ニュース

求人媒体・SNS・検索結果は発見目的に限り、公開根拠は公式ページで確認する。ログイン、制限回避、過剰アクセスを行わない。

## 2. 差分候補を作る

前回データと比較し、追加・変更・終了候補を作る。各候補に以下を含める。

- 企業名
- 求人タイトル
- 変更種別
- 公式URL
- 初回確認日
- 最終確認日
- 公式確認できる事実
- `Genba分析`がある場合は事実と分離した説明
- 確信できない点と公開リスク

推測で空欄を埋めない。求人票の本文を大量にコピーしない。

企業詳細の公開情報インテリジェンスを更新する場合は、公式決算・法定開示・日本向け求人・国内導入事例を優先し、必要に応じて外部集計とコミュニティ情報を補助的に使う。`Genba仮説`ごとに支持材料、反証・留保、面接検証質問、対象地域、確認日を揃える。既存仮説に反する新情報を見つけた場合も削除せず、確度または結論を更新する。

## 3. 公開候補を更新する

確認済みの変更だけを`lib/market-data.ts`へ反映する。

- 同一求人を重複登録しない
- 公式URLが生きていることを再確認する
- 日付は実際の確認日に合わせる
- 募集終了求人は即時削除ではなく、将来の履歴設計に沿って終了扱いを検討する
- スポンサー企業でも通常企業と同じ事実確認基準を使う

データ構造を変える場合は、`docs/10-website-renewal-spec.md`も更新する。

## 4. コンテンツ候補を作る

毎日作る候補:

- 変化フィード
- 新規・変更求人の短文紹介
- X投稿下書き2〜3本

毎週作る候補:

- Genba Sales Brief
- 今週の求人差分
- 注目企業1社
- 外資AE向け海外一次情報の要点

編集記事は週1〜2本を上限目安とし、記事数を埋めるために作らない。既存英語記事はアーカイブ扱いとし、新規コンテンツは日本語を基本とする。

X原稿は`content/x/drafts/`へ保存し、明示依頼がなければ投稿しない。

## 5. 必須ガードレール

公開候補ごとに確認する。

- 公式出典がある
- 確認日がある
- 事実と分析が分離されている
- 給与・OTE・言語・勤務形態を推測していない
- 求人票・記事・画像を無断転載していない
- 非公開情報、顧客情報、個人情報、現勤務先情報を含まない
- 広告・スポンサーは明示されている
- 応募仲介、候補者提供、成功報酬に当たる処理をしていない
- 固有名詞、数字、日付、リンクを再確認した

1つでも確認できない項目があれば、その候補は公開せず、理由を報告する。

## 6. 検証する

1. `npm run validate:agents`
2. `npm run build`
3. `git diff --check`
4. 変更した内部リンクと外部公式リンクを確認する
5. `git status --short`で対象外の変更が混ざっていないことを確認する

検証失敗時は公開しない。既存の正常な公開データを壊して完了扱いにしない。

## 7. 承認・公開する

依頼にpush・公開の明示承認が含まれる場合だけ、今回の対象ファイルを明示してステージし、コミット・push・デプロイ確認まで行う。

承認がない場合:

- 下書き・実装・検証まで完了する
- 公開候補、出典、変更件数、リスクを報告する
- push・公開前で停止する

公開した場合は、トップ、企業、求人、シグナル、変更対象ページの正常応答を確認する。

## 8. 報告する

以下を簡潔に報告する。

- 追加・変更・終了した企業／求人
- 作成したコンテンツ下書き
- 使用した公式出典
- 公開しなかった候補と理由
- 検証結果
- コミット・push・本番反映の有無
- Jioの判断が必要な項目
