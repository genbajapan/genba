# 企業ページ「想定できる売り方」標準

最終更新: 2026-08-14

このファイルは、企業ページの`sellingPlaybook`における課題啓蒙の正本である。Salesforce個別ページを起点に改善してきた表示フォーマットと分析順序を会社名に依存しない共通仕様として固定し、全社で統一する。Salesforceページの公開有無にかかわらず、本ファイルを優先する。

## 1. 課題啓蒙の3視点

`issueLenses`は、以下のタイトル・順序を完全一致で使用する。

1. `既存顧客の導入目的から見る課題`
2. `製品の成り立ちから見る課題`
3. `外部環境の要求から見る課題`

### 既存顧客の導入目的から見る課題

- 公式顧客事例から、顧客が実際に変えたかった業務、KPI、意思決定を抽出する
- 製品機能の説明ではなく、導入前の状態と買う理由を書く
- 複数事例に共通する課題を優先し、単一事例しかない場合は一般化の限界を明記する

### 製品の成り立ちから見る課題

- 創業理由、最初に解こうとした問題、設計思想、主要な製品拡張の理由から課題を読む
- 現在の機能一覧ではなく「なぜこの製品が必要になったか」を書く
- 公式のAbout、創業者発言、製品発表、法定開示を優先する

### 外部環境の要求から見る課題

- 企業や製品の外側で起きている変化を起点にする
- 対象例は、法規制・ガイドライン、経営や投資家からの説明要求、技術標準の変化、顧客行動、労働力・人口動態、セキュリティ・データ主権、競争環境など
- `外部変化 → Buyerに生じる要求・説明責任 → 放置した場合の事業課題 → 投資テーマ`の因果を一続きで書く
- 自社の製品roadmap、資金調達、採用拡大、機能追加だけを「外部環境」と呼ばない
- 時点依存の事実は、公開前に最新の公的機関・企業公式・法定開示で再確認する

## 2. 課題から選定までの4段階

`narrative`は、以下のラベル・順序を完全一致で使用する。

1. `背景`
2. `課題`
3. `解決策`
4. `選定の理由`

- `背景`: 外部環境と顧客の現状を示す
- `課題`: 現状のままでは何が失われるかを、業務・財務・リスクで示す
- `解決策`: 製品が課題をどう変えるかを、導入後の業務状態として示す
- `選定の理由`: 代替手段・競合と比較し、当該製品が選ばれる条件を示す

## 3. 補助要素

- `frameIntro`: 製品説明ではなく、最初に顧客課題を一文で置く
- `openingHook`: 顧客が未認識の損失・risk・説明責任に気づく質問にする
- `valueHypothesis`: 顧客事例のKPIまたは検証可能な指標と結びつける
- `commonObjection`: 反論への反証ではなく、比較すべき論点・測定方法へreframeする

## 4. AE向けFABE表示

- 企業一覧カードは、顧客課題とそれを解く主力製品・テクノロジーを一文で完結させる。`課題「...」`等の項目ラベル、会社名から始まる一般紹介、省略記号を使わない
- 企業上部のセールスサマリーは、全社共通で「常時表示」と「クリック展開」の2層に分ける。会社ごとに独自レイアウトを作らない
- 常時表示は、対象顧客と課題3点、主力製品のFeature、競合とのAdvantage、顧客のBenefitを4文で記載する。会社名から始めず、Evidenceや市場説明を混ぜない
- クリック展開の見出しは`導入実績・成果指標・日本市場の見立てを見る`とし、開いた後は`導入実績・成果指標・日本市場の見立てを閉じる`へ切り替える
- クリック展開は、導入前後で測るKPI、企業公式・法定開示等のEvidence、日本市場の需要・実績・未公開情報の限界を記載する
- 常時表示と展開表示はどちらも省略記号で切らず、各文を述語まで完結させる。情報が未公開の場合は推測せず、その限界を明記する
- 各`solutions`は、`Feature(機能)`、`Advantage(優位性)`、`Benefit(メリット)`、`Evidence(証拠)`、`Competitor(競合)`の固定順で表示する
- Evidenceに会社全体の成長率や導入社数を使う場合は、個別製品の成果ではないことを区別する。製品単位の根拠がなければ、推測で補わず未公開と明記する
- Competitorは社名・製品名の列挙だけにせず、実データで比較すべき設計、統合、運用、コスト、ガバナンス等の軸を併記する

## 5. 公開前チェック

- 3視点と4段階が標準タイトル・順序になっている
- 外部環境が企業内部の施策や製品機能にすり替わっていない
- 事実、Genbaの読み、仮説が混同されていない
- 給与・顧客KPI・市場数値を推測していない
- 課題啓蒙がfear sellingだけにならず、顧客が検証できる問いと指標を含む
- 全ソリューションにFABEとCompetitorの5項目があり、各説明が空文字ではない
- 全企業の上部に4文の常時表示と、成果指標・公開根拠・日本市場を含むクリック展開がある
- 全企業の一覧カードが、課題と主力製品のテクノロジーを一文で説明し、旧ラベルや省略記号を含まない
- 常時表示が会社名から始まらず、展開前にEvidenceを詰め込んでいない
- `npm run validate:playbooks`が成功している
